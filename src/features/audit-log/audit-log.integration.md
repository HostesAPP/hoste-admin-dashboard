# Audit Log Design Update

The server route `/audit-logs` supplies a typed snapshot to the feature-level client screen. Existing Settings/System/Security audit links still reach this route. The sidebar treats it as part of Settings, matching the reference. No separate mobile layout or dependency was added.

The full PRD is not present locally; README specifies a read-only, append-only, immutable audit log. Existing raw `AuditLogItem` records and action strings are preserved. Labels map those strings for display without modifying their source values. The supplied screenshot's summary metrics are a separate mock aggregate snapshot, not a total inferred from the four available records. The table and exports count the actual filtered source records. Historical date filtering is anchored to the snapshot's reporting day rather than today's date and uses Africa/Lagos (WAT) day boundaries.

Search, staff/action/entity/date filters, clear, page size, bounded pagination and CSV export are functional with mock records. CSV exports all filtered rows, retains raw identifiers/action codes/UTC timestamps/IP values, escapes CSV cells and guards formula injection. The Details dialog is read-only and includes full notes plus metadata omitted from the compact table. No record mutation, deletion, synthetic audit event, or invented before/after fields were added.

Details now opens the screenshot's right-side inspection drawer via the existing accessible Dialog primitive. Each drawer uses the selected record, displays the WAT timestamp with seconds and its derived Unix timestamp, and preserves staff IDs, action, entity, notes and IP. Close, Escape, backdrop dismissal, focus trapping and focus return use the Dialog primitive. The bottom close control remains outside the scrollable content.

`snapshot.inspections[recordId]` may optionally supply presentation metadata for staff name/role, affected-subject snapshot, IP hash, session ID and origin route once available from an authorized source. These are optional display fields from the screenshot, not new database/API contracts. Current records do not include them, so the drawer shows "Not recorded" rather than generating identities, hashes, session IDs, routes or status transitions. A Unix timestamp is a format conversion of the recorded time; no new audit event is created.

Replace the route's mock snapshot with authorized backend data when the approved contract is available. For large datasets the backend must own filtering/pagination and return actual filtered totals and the requested records; this preview currently filters local records. Backend authorization must enforce the PRD's audit-log access restrictions and immutability; this frontend redesign does not add or weaken existing route authorization. Summary metrics must be supplied by the backend, not computed from one page.
