# Referral Earnings Preview

`ReviewPage` supplies the earnings snapshot to `ReferralsOverview`, which renders the `ReferralEarnings` component for the new tab. As requested, every earning record's View action opens the global Referral & Payout Configuration screen shown in the second screenshot, not an invented individual earning-details page. Back to Earnings retains the current filters and page; unsaved configuration edits require discard confirmation.

The full PRD is not present locally. These types are presentation models based on the screenshots and existing referral patterns, not proposed backend contracts. The supplied six earning rows reuse directory referrer IDs. Aggregate KPI snapshots (842 rewards / ₦842,000 total) are separate from the six available preview records; pagination and exports use the real filtered record count. The existing payout fixtures are aggregate transactions and are not used to infer individual earning settlement status. Historical mock periods are anchored to September 2, 2026. Date filters apply to earning rows and the chart; supplied KPI snapshots are unchanged.

`EarningsAdapter` separates load/save from presentation and uses the existing TanStack Query cache. Replace it with approved authorized backend operations when available. `canManage` is a supplied preview permission flag, not a security boundary. Both the form and mock save enforce read-only access. Loading refresh feedback, cached-data refresh errors/retry, empty results, and validation/save failures are supported.

Configuration uses React Hook Form and Zod. Saving updates only the in-memory preview configuration and cache. It does not change historical rewards, approval states, payouts, or notification delivery, nor does it make gateway calls or create audit records. Eligibility evaluation, threshold enforcement, payout calculation/execution, authorization, audit logging, and notifications remain backend-owned. The screenshot's ₦1,000 reward and ₦5,000 minimum, manual processing, enabled bank transfer, criteria and switches are mock configuration, not new production policy. Settings are global to the program, even though reached from a record's View button. Saved settings last only for this preview session.

The chart uses Recharts and existing theme variables. Tables, controls, status badges, pagination, and CSV escaping reuse existing referral components/utilities. No dependency or small-screen redesign was added.
